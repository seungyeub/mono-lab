## 2. 프레이밍 — 이걸 지키지 않으면 역효과다

"포트폴리오 사이트를 만들었습니다"는 흔한 클리셰이고, 자칫 **채울 것이 없어서 넣은 것처럼** 읽힌다. 카드의 주어를 바꿔야 한다.

- ❌ 포트폴리오 사이트 — Next.js로 만든 개인 웹사이트
- ✅ **mono-lab — AI 협업 워크플로와 품질 게이트를 실증한 모노레포**

사이트는 **산출물**이고 본체는 **개발 방식**이다. 이 프레임에서는 "지금 보고 있는 이 페이지가 그 산출물"이라는 자기참조가 어색함이 아니라 근거가 된다.

### 정직성 원칙 (App Review Tracker와 동일 적용)

코드 작성 주체가 AI라는 사실을 명시하고, 본인 기여는 **검증·판단·방향 결정**으로 서술한다. 숨기면 리스크지만, 그것이 카드의 주제라면 강점이 된다.

## 3. 카드 구성안

### 3-1. Key Highlights 후보 — 도구가 알려주지 않아 사람이 판단한 기록

카드의 힘은 여기서 나온다. 모두 저장소 이력으로 확인 가능하다.

1. **CI 정체의 원인을 규명하고 방향을 바꾼 것** — `playwright install --with-deps`가 반복 정체(37/21/10분)했을 때 재시도·락 정리로 해결을 시도했으나 미러 대역폭이 실제 원인임을 실측으로 확인하고, "일시적"이라던 판단을 철회한 뒤 공식 컨테이너 전환으로 방향을 바꿨다 (PR #49)
2. **VRT baseline 오염 진단과 자기 정정** — 스냅샷이 깨진 원인을 mix-blend-mode로 진단했다가 틀렸음을 확인하고, PageLoader 오버레이가 찍힌 것임을 규명해 대기 조건을 추가했다 (PR #47)
3. **baseline의 기준 환경을 규명하고 문서화** — 같은 코드가 macOS와 CI 컨테이너에서 다르게 렌더링되어(래스터라이저 차이로 한글 문단 줄바꿈이 누적 변동) 로컬 실패가 정상임을 밝히고 개발 가이드에 명문화했다
4. **허용치가 회귀를 숨기는 문제** — `maxDiffPixelRatio: 0.05` 때문에 리빌이 발화하지 않은(요소가 빠진) baseline이 갱신되지 않고 굳는 것을 발견해, baseline을 폐기하고 재생성하도록 했다
5. **자동 리뷰의 취사선택** — CodeRabbit 지적을 무조건 수용하지 않고 반영/미반영을 판단해 근거를 PR 코멘트로 남겼다

## 4. 실무적으로 정리할 것

1. **order 재배치** — 이 프로젝트는 2026-05 시작으로 App Review Tracker(2026-07)보다 빠르다. 현재 order 1이 ART이므로 순서 조정이 필요하다.
2. **홈 노출 짝수 유지** — `FEATURED_SLUGS`가 현재 8개(짝수)다. 홈이 2열 격자라 홀수가 되면 마지막 줄이 빈다. 이 카드를 홈에 노출한다면 하나를 빼거나 10개로 맞춘다.
3. **자기참조 링크** — liveUrl을 이 사이트 자신으로 걸지, github만 걸지 결정한다.
4. **저장소 공개 범위** — 현재 공개 상태를 유지할지 확인. 비공개로 돌리면 이 카드의 핵심 근거(검증 가능성)가 사라진다.

### 실무 정리 결과

- **order** — `mono-lab`을 **2번**에 넣고 `yoga-editor`~`vanillapet`을 한 칸씩 밀었다(2~10 → 3~11). App Review Tracker(2026.07)가 mono-lab(2026.05)보다 나중 시작이라 1번을 유지한다.
- **홈 노출** — **넣지 않는다.** `FEATURED_SLUGS`는 홈 2열 격자 때문에 짝수여야 하고 이 계약은 `mdx.test.ts`가 강제한다. 추가하면 9개가 되어 기존 8건 중 하나를 빼야 하는데, 남은 8건이 이미 선별된 결과라 Archive(`/work`) 노출로 충분하다고 판단했다.
- **자기참조 링크** — `liveUrl`(이 사이트)과 `github`(저장소)를 **둘 다** 건다. 검증 가능성이 이 카드의 핵심이므로 저장소를 감출 이유가 없다.
- **저장소 공개 범위** — 공개 유지.
